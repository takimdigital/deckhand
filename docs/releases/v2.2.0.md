# Deckhand 2.2.0 — proven paths, and runs that improve them

**Workflows.** At the start, `dh workflow query` returns the 3 proven paths that best fit the project: yours, the
ones shipped with Deckhand, and the community's. The owner picks one, and the AI follows it step by step. Each step
has the exact command and what it must print; the steps tick themselves as `dh` runs them. The AI spends its
thinking on the words, the design and the business, not on rediscovering the path.

**The workflow autopsy, at any moment.** `dh autopsy --workflow` replays the session without any model. It shows what
the owner was asked and answered, which answers came too late and re-opened work, where the run left its workflow,
and what each failure cost. It then proposes fixes to the workflow, each with its reason and evidence. The owner
chooses where accepted fixes go: their own workflows, a community pull request, or nowhere. It reads Claude Code
sessions, Hermes' own session store and any chat log.

**Field fixes.** A real Hermes run on Windows was dissected to the tool call. Its 20 problems are fixed, each with a
regression test:

- a gate passed on the agent's paraphrase of a change request;
- a base that could not land in the planning folder;
- a database kept alive by hand;
- Windows-reserved ports;
- 22 work packages for 4 builders;
- the git-bash `HOSTNAME` trap;
- …and more.

Parallel builders now get exactly N packages that never share a folder, plus one conventions file.

**Any harness, its own syntax.** `dh next` prints the detected harness's own commands, so Hermes gets
`terminal(background=true)` + `process_manage`, never `nohup`. The v1 `deckhand-profile` skill is fully absorbed:
`~/.deckhand/pending.md` and `profile.md` keep working through `dh pending` and `dh profile`.

Upgrade: re-run `install.sh` / `install.ps1`. An old copy of any v1 skill (deckhand-profile, buildout, vps-ops,
session-autopsy, component-library) still installed in an agent can be deleted.
