# Deckhand 2.2.1 — try-on: the owner's page never stays broken

An owner tried try-on on their Next 16 app and hit three errors. Each one was replayed in a real browser against a
Next 16 dev server, fixed, and covered by a regression test.

**Footer swap no longer fails with "is not valid JSON".** Links like `tel:${c.phone}` and labels like `{c.phone}`
now travel as code, so the design shows the real phone number and email. The owner's link columns (Contact,
Company) flow into a design's single link list, so footers that used to be skipped now carry the owner's links.

**Discard, then pick again, just works.** The overlay tells the engine what was clicked, not only where. When the
page is older than the file (a try added and removed lines), the engine finds the element again. When it cannot be
sure, it says so and offers **Reload the page and pick again**; it never swaps the wrong element. After Keep or
Discard, the next pick reloads the page first.

**A design can no longer break the owner's app.**
- Before a design is shown, everything it imports is checked from the project: a missing icon, a missing Radix
  part, or a package that is not installed means the design is skipped and the next one is shown.
- Designs that need no install come first. With the `radix-ui` umbrella installed, Radix parts come from it.
- Then the page itself is loaded: if it stops building, the file is restored at once and the try reopens without the
  designs that broke it.
- A package installed for a try is named, never silently left behind.

Upgrade: re-run `install.sh` / `install.ps1`, then restart `tryon serve`.

Was your app left broken by the old version? Run `node <skill>/tryon/cli.mjs status --project .`, then
`discard --id <id>` for any open session (or `clean`), and restart the dev server.
