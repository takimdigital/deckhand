# 00 — Ideation: evidence of demand before product code

Load when: shaping a concept, validating an idea, or scoping an MVP.

## Constraints (hard)

- No product code before a demand signal exists (interviews + at least one behavioral signal).
- One job per MVP. Everything else goes on an explicit *not-building* list.
- Every assumption is written down with a test and a threshold.
- Kill criteria defined BEFORE validation starts, or the exercise is theater.

## Procedure

1. **Problem statement + ICP.** Narrow to a person in a situation (not "everyone"). One sentence.
2. **Current alternatives (JTBD).** What does the ICP do today instead? "Nothing" is a red flag unless the pain is acute.
3. **Pain test.** Frequent + urgent + expensive (time/money/risk). If not all three, go narrower.
4. **Validation ladder** (each rung costs more, proves more):
   problem interviews (never pitch) → fake door / waitlist with real traffic → concierge run (manual delivery) → paid pre-commitment.
5. **Wedge.** One persona, one job, one channel for reaching them.
6. **Positioning statement.** "For [ICP] who [situation], we [outcome], unlike [alternative], because [mechanism]."
7. **MVP scope.** The smallest end-to-end thing that delivers the one job. Write the not-building list explicitly.
8. **Metrics + kill criteria.** e.g. "≥8/12 interviewees describe the problem unprompted"; "≥X% waitlist→trial"; "kill if <N paying users by D+30".

## Anti-patterns

- Pitch-mode interviews (you learn nothing; people are polite).
- Feature lists disguised as vision; building a platform before a product.
- Vanity metrics (signups, pageviews) vs actionable metrics (activated, paid, retained).
- Leading questions; no written notes; no thresholds.
- "No competitors" — that usually means no market or no search effort.

## Jargon (use precisely — see `jargon/web-saas.md`)

ICP · JTBD · wedge · validation ladder · willingness-to-pay · concierge MVP · PMF (Sean Ellis-style 40% test as ONE signal, not proof) · kill criteria · vanity vs actionable metric.

## Verify

- Raw interview notes exist (N ≥ 10 ideally), not summaries.
- A written demand hypothesis with numeric thresholds + kill criteria.
- One-sentence problem statement and positioning, agreed with the founder/user.
