# 50 — The Direction Competition (two directors, one winner)

Load: at the DIRECTION stage — after the map (`45-map.md`), before the lock freezes (ref `10-design-assembly.md` Phase 1). **Default: ON whenever a brief exists** (greenfield/rebuild — the normal case); skipping is a recorded decision — who/why, one line in `direction/log.md` beside the skip note. A run without it uses the single-designer Phase 1 path unchanged — say which path ran in one line.

**Why:** one first draft is rarely the strongest direction, and quality comes from argued documents — never from a second build. Two directors with different instincts argue into ONE direction; the losing positions don't evaporate — the second director takes the independent-verification lane.

## The shape (hard rules)

1. **Two directors, EQUAL power.** ORCH-A and ORCH-B. Same inputs — brief, acceptance criteria, the map (`45-map.md`; **when no map exists, substitute the brief + the settled decisions (+ the shipped lock on rebrands) and RECORD the substitution — rule 7 then reads N/A → single team**), constraints (budget, bans, client pins). They diverge ONLY on mandate + design seed. **Blind drafts:** neither sees the other's draft until both are complete (single-agent runs: finish A, then write B WITHOUT revising A, then compare). **Blinding witness (owned):** the run host records each draft's `sha256` + completion timestamp at the moment that draft completes — BEFORE the other draft is read; the scribe re-verifies both hashes at merge start and records them in `log.md` under a `Blinding witness` heading together with the measured composition order. mtimes alone may not witness blinding; a single-writer run says plainly that mandate separation ≠ agent independence and marks itself DEGRADED (rule 11). Independent starts are where the gains live; a sequential revision chain is a documented harm.
2. **Compete on DOCUMENTS ONLY**: `direction/A.md` and `direction/B.md`. Never two builds — a second full build is the one thing this protocol must never cause (it competes on direction, not on code).
3. **Forks are the only currency — capped at ~5.** Every disagreement resolves into a NAMED fork: question, position A, position B, evidence, cost (the table's `criterion` and `cost` columns carry these). Per fork, **pre-commit the criterion that will decide it BEFORE reading the other position**; 2–3 rounds max, adaptive stop — re-litigating a settled fork is a failure mode, not rigor. "Vibes without a fork are out of order" — an objection that can't be written as a fork is not an objection.
   **Fork governance:** when both drafts pre-commit DIFFERENT criteria for one fork, the scribe records both and resolves: (1) the criterion anchored in pre-existing pins (brief / acceptance / bans) wins; (2) both-or-neither → the more test-shaped criterion wins — recorded with why. **Over-cap demotion order** (proposals > ~5): re-litigations drop first, then candidates with no pre-committed criterion from either draft, then lower cost-impact — every demotion recorded in `decision.md` with its evidence, and a contested demotion may be raised back to a fork before the merge.
   **Evidence-or-downgrade:** every position cites an artifact (spec line, user quote, prior decision, test, link); un-evidenced claims are tagged `[unverified]` and cannot decide a fork.
4. **Merge by mechanism to exactly ONE**: a per-fork rubric (the pre-committed criteria) plus a **fusion step** that justifies every retained element from either draft — **neither author merges alone** (the pair together, or a neutral facilitator). The **winner's seed travels** into the merged lock — the loser's seed retires with its doc (precedence over ref 10's "chosen at lock time": with a competition, the winner's doc is the origin). Output: `direction/final.md` + `.design/design.lock.json` + `direction/decision.md`. The lock is **FORMAT-COMPATIBLE** with ref 10's schema — no removed or renamed keys; new keys optional. A site cannot ship two directions.
5. **Tiebreak:** an irreconcilable fork escalates to the client as ONE question — two plain-language options, one tradeoff line each, never internal ids. Delivered on the team board (`#escalations` + flag) when a board exists, else as a `PENDING.md` item `DECISION: <fork>`; either way it also appears in the client report. Skip = explicit decline OR no answer by freeze → the rule-based default applies (brief pins first, acceptance criteria second, lower cost third), recorded as `default-by-rule` in `decision.md`. Never a silent coin flip.
   Worked example — `DECISION: motion`: Option 1 "nothing animates" (calmest; a form send may feel unacknowledged) · Option 2 "one short receipt animation after sending" (clearer confirmation; one motion more than you mentioned). No answer by freeze → Option 1 (brief pin).
6. **After the merge the lanes split — never dual-command one lane:** ORCH-A chairs the build (ref 10; one writer per artifact). ORCH-B owns the **INDEPENDENT VERIFICATION** lane — re-runs the acceptance rows against the built product and reports to the CLIENT, not to ORCH-A (that independence is the mechanism; route it through nobody). Default posture = **refutation**: every finding cites artifact + location, and "looks good" is not a verdict.
7. **Parallel multi-team build is a MODE, not a default:** allowed only when the map exists AND shows ≥2 truly independent workstreams AND the shared foundation is frozen. No map, or foundation not frozen → single team (state which). The trigger is mechanical — never "by vibes".
8. **PASS_2 before freeze:** both docs' design-intent sections must state **concrete candidate values** (palette hexes, type families, radius, motion) — conversion-audit ref 10's 5 tells are token-level, so PASS_2 would be un-runnable against prose; run the anti-slop pass (5 tells, restraint rule, quality floor) against the WINNING plan; record it (`direction/pass2.md`) with artifact+location citations and what it changed (the gate enforces ≥2 citations). The built-result anti-slop re-check (INV-8) stays in BUILD/VERIFY.
9. **Cost + vindication log** (`direction/log.md`): stage cost (tokens, wall-clock) recorded when the stage ends; a `vindication:` field filled when the outcome is known (the change path or the next field-test verdict names which direction was right). **If the merged direction is not measurably better than the better single draft, say so plainly** — an unfalsifiable debate stage is theater.
10. **Minority report:** `decision.md` carries, per fork, the losing option + the evidence that would REOPEN the decision. A settled fork stays settled unless that evidence appears.
11. **Authorship + independence:** one NAMED scribe writes `forks.md` / `final.md` / `decision.md` (the project's PM role; fallback ORCH-A — record who). Directors author only their own positions and never edit the other's text; nothing overrules a rubric outcome — a dispute escalates. When the runtime supports it the two drafts have separate writers, each timestamped at write as the blinding witness; a single-writer run is **DEGRADED MODE** — recorded in `log.md` and flagged in the report. Fork-cap demotions (concession/pin) are recorded with evidence; a contested demotion may be raised back to a fork before the merge.
12. **Upstream changes mid-run — conform append-only:** new requirements are appended and tagged (`[addendum N]`), never rewritten into a position; the record keeps what each draft said before the change (this ref's own addendum pass is the pattern).

## Artifacts (in `direction/` at the project root — the merged lock's content ships as `design.lock.json` beside it; the freeze finalizes it to `<project>/.design/design.lock.json`) — greenfield: `.design/` is created at that freeze step.

| File | Contents |
|---|---|
| `A.md` / `B.md` | direction docs, **≤150 lines binds** (≈2k tokens is an estimate, not a second limit) each: positioning (1 paragraph) · priorities (ranked) · design intent (**concrete candidate values** — palette hexes, type families (display/body/mono), radius/motion direction; tokens are set at assembly) · style picks (tag-level leanings from the refs' vocabulary — **hypotheses**; the registry picker only runs at assembly) · **fork proposals** (each with the criterion you pre-commit before reading the other draft — liftable rows for the scribe) · risks · seed |
| `forks.md` | `\| # \| fork \| criterion (pre-committed) \| position A \| position B \| evidence \| cost \| resolution \|` — every row resolved or escalated; never a raw `\|` inside a cell |
| `final.md` | the winning direction (a `winner:` line) + one line per rejected MANDATE-level position + why |
| `decision.md` | the decision record: per fork — chosen / rejected / why + the **minority report** (losing option + the evidence that would reopen it); escalations + `default-by-rule` entries |
| `pass2.md` | anti-slop results + revisions made |
| `log.md` | stage cost (tokens, wall-clock) + `vindication:` mark (filled later, from the change path / field-test verdict) |

**Gate — mechanized** at freeze by the same script as the map arm: `py <buildout>/scripts/map_check.py --direction direction` — **run from the PROJECT root** (paths are project-relative; the script's path is passed explicitly) (both arms together: `--map map --direction direction`; each arm is skip-graceful — no map → SKIP, no direction → SKIP "single-designer path", exit 0 — and it can never pass vacuously when artifacts ARE present). Both arms on the shipped fixtures, from the skill's own dir: `py scripts/map_check.py --map tests/fixtures/map-lean --direction tests/fixtures/freeze-project/direction`. The direction arm enforces: the 7 artifacts exist (a merge-time self-check may run `--allow-missing pass2` before PASS_2 exists; the FREEZE run is strict) · the forks table carries `criterion` + `cost` columns, every row resolved, ≤~5 rows · exactly ONE live `winner:` **at the start of a line** (prose mentioning the winner is fine; any other doc declaring one must be annotated `retired`) · `decision.md` carries the minority report · `log.md` carries cost + the `vindication:` field + the **blinding witness** (two draft hashes, or a DEGRADED statement) · `pass2.md` carries ≥2 artifact+location citations · the merged lock parses, keeps every ref-10 key (no removed/renamed; colors 6-hex), validates optional `dark` (the six color keys, 6-hex) and `focus_ring` (6-hex) when present, and passes the ref-10 enums (`randomness`/`density`/`motion`; `seed` int; `vibes` list; `base` ∈ {`radix`, `none`}). A FAIL refuses the freeze — fix the artifact, not the gate. (A table cell must not contain an unescaped `|` — escape it as `\|` and the gate honors the escape.) What the script cannot judge is owned, not unstated: escalation quality → the scribe/PM before freeze · blinding + fusion quality → the scribe at merge · PASS_2 revision quality → ORCH-B's verification lane.

## The two casting briefs (defaults — the pair must differ on the axes the brief left open)

- **A — trust-first:** sober, conversion-calm, evidence-forward; priorities = clarity, speed-to-trust, low friction.
- **B — distinctive:** character-led, memorable, identity-forward; priorities = recall, voice, one deliberate surprise.

Neither is "the safe one" — both must be defensible against the brief. Each casting brief carries: goal · shared inputs · the mandate · the artifact schema · stop condition ("a direction doc ≤150 lines + fork proposals") · token budget (**≤150 lines/doc binds**; ≈2k tokens is an estimate; no research beyond brief + map — naming known OFL families from memory is expected; the `license` line is EXPECTED at DIRECTION, verified at assembly, never fetched). Style picks at this stage are tag-level HYPOTHESES from the refs' own vocabulary — the registry picker only runs at assembly; no catalog fetch happens at DIRECTION; say so in the docs.

## Where it sits in the flow

UNDERSTAND → MAP (`45-map.md`) → **DIRECTION (this file)** → FREEZE (`map_check.py` + lock + ownership) → BUILD (ref 10; one chair) → VERIFY (`30` + `40`; independent lane) → STORE / LIVE.

Skip rule: no competition this run → record `single-designer path` in `direction/log.md` (when no `direction/` exists at all, in one line where the lock is written — ref 10 Phase 1); behavior otherwise unchanged.

## Reading map

- Reads: `conversion-audit` `10-design-execution` (anti-slop PASS_2 + design-execution boundary) · ref `10-design-assembly.md` (lock schema) · the map (`45`) · **the acceptance criteria — a REQUIRED input (the project's acceptance file — e.g. `case/acceptance.md` in case-study layouts — or the client checklist; when only a brief exists, the rows derive from it).** Citations cite refs by filename stem (`10-design-assembly` vs `10-design-execution`) — bare "ref 10" is ambiguous across packs.
- Read by: `40-verify-the-product.md` (the verification lane re-runs the same rows) · team-protocol usage (board/flags mechanics unchanged — this is a usage pattern, not a protocol change).

## Pitfalls

- Two builds ("let the winner emerge in code") — forbidden; it is the exact cost this protocol exists to avoid.
- Unnamed disagreements ("B's version feels better") — write the fork or drop it.
- The merge papering over an open fork — an unresolved fork escalates; it never averages.
- Letting ORCH-B's verification report pass through ORCH-A — it goes to the client undiluted.
- The lock's `vibes` vocabulary can't carry a fine outcome — keep the nearest two words in the lock and carry the real axis in `final.md` prose; never invent enum values the assembly can't consume (a genuinely missing bucket gets added to ref 10 append-only, as `institutional` was — same rule when NEITHER candidate bucket fits a direction).
